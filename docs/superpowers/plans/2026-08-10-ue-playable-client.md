# План: довести клиент на Unreal до играбельного состояния

> **Для исполнителя (Opus 5).** Это handoff-документ: он содержит проверенные
> факты окружения, список известных ловушек и поэтапный план. Прежде чем
> менять код — прочитай разделы «Факты» и «Ловушки» целиком: почти каждая из
> них уже стоила кому-то часов. Ветка `codex/scene-task3-impl` — основная
> линия; ветка `fix/ue-visuals` в основном worktree — архив, из неё уже
> перенесено всё нужное.

**Цель.** Пользователь запускает клиент, входит в мир, ходит по Garner,
дерётся, подбирает вещи, говорит с NPC — и параллельно может улучшать ассеты
(конвертер → импорт → расстановка) и пересобирать сервер.

**Критерий готовности всего плана:** цикл «вход → бег по городу → выбор
цели → убийство моба → подбор дропа → надеть вещь → диалог с NPC → переход
на соседнюю карту → выход → повторный вход в той же точке» проходит вживую,
без правок кода между шагами.

## 3. Ловушки (каждая уже выстрелила)

1. **Headless-скрипты UE молчат.** `unreal.log` не доходит до stdout;
   коммандлет печатает «успех» всегда. Каждый скрипт пишет отчёт в
   `CorsairsUE/Scripts/reports/<имя>.txt` — читать ЕГО, не stdout.
2. **Реестр ассетов в headless пуст**, пока не вызван
   `scan_paths_synchronous([...], force_rescan=True)`. Без этого обходы
   находят 0 ассетов и рапортуют «изменено 0» — неотличимо от успеха.
3. **Умолчание страничного писателя рельефа — зеркало.** `terrain-reference`
   без `--coordinate-profile rigid-q` печёт страницу в базисе Task8Legacy.
   Это сознательный контракт (тесты `RigidQIsOptInAndKeepsTask8Default`,
   `DefaultRemainsTask8Legacy`) — НЕ менять умолчание, всегда передавать ключ.
   Обычная конвертация каталога (`WriteTerrainMesh`) уже на Q без ключей.
4. **47 старых `.umap` в `Content/Maps/` собраны зеркальным базисом** —
   они невалидны и подлежат пересборке (этап 3). Не использовать как эталон.
5. **`AccountServer` падает молча**: `ObjectDisposedException` на
   `RemoteEndPoint` закрытого сокета (`ChannelIO.fs:22,31`,
   `AccountHostedService.fs:267→285`). Процесс жив, порт слушается ядром,
   главный цикл мёртв → «проверка учётной записи» висит вечно. Диагностика:
   `tail server/logs/Account.log`. Лечение до починки: перезапуск стека.
6. **`.block.raw`/`.terrain.json` в `.gitignore`, а `LoadCharacterGround`
   fail-closed** — на карте без этих файлов вход в мир не состоится, и
   симптом выглядит как «клиент не подключается». Генерация:
   `install_runtime_map_data.py`.
7. **Часть python-тестов — grep/AST по тексту скриптов**, не поведение.
   Зелёный прогон не доказывает семантику; проверять мутационно.
8. **`Angle` в протоколе — целые градусы.** Любое появление `/ 10` рядом с
   углом — регрессия (уже дважды вычищали).
9. **Эффекты (`type=1` в манифесте) — не постройки**: своя таблица, своя
   нумерация. Конвертер scene-manifest уже разводит их fail-closed.
10. **PCH:** в C++-проектах `stdafx.h` подключён через `/FI` — не добавлять
    `#include "stdafx.h"` руками. **RC-файлы** править только `sed`.
11. **Winding после Interchange не измерен** (см. этап 1) — не наслаивать
    правок обхода треугольников, пока нет замера.
12. **Мёртвый код:** `UCorsairsTerrainHeights` (CorsairsImport) не имеет ни
    одного вызова; боевая высота — `CorsairsCharacterGround`. Не расширять.

### Этап 1. Визуальное подтверждение базиса (блокирует всё остальное)

Сейчас «базис верен» — вывод из кода и тестов; ни одного кадра на повёрнутом
базисе не снято. Ровно тот класс молчаливых дефектов, где зелёный прогон
ничего не доказывает (см. `memory/conversion-pitfalls`).

1. Пересобрать эталонный квартал текущими скриптами:
   `place_scene_progress_city.py` → `apply_scene_material_modes.py` →
   `place_scene_progress_npcs.py` → `capture_scene_progress_city.py`
   (пути запуска — в докстрингах; отчёты в `Scripts/reports/`).
2. Прогнать `verify_scene_progress_{camera,lighting,terrain}.py` — PASS.
3. Сравнить снятый кадр с эталоном живого клиента
   `artifacts/visual-progress/reference/garner-live-reference-2026-08-09.png`:
   ориентиры (фонтан, клумбы, синие крыши) на своих местах, город НЕ зеркален.
   Численно: доля «красных» пикселей сопоставима с эталоном (~0.04 %).
4. **Замер winding:** посмотреть на рельеф эталонной страницы сверху и снизу
   (скриншот из редактора). Земля видна сверху → обход верен. Земля видна
   только снизу → разворот в `TerrainMeshWriter.cpp`/`TerrainPageMeshWriter.cpp`
   инвертирован — чинить парой к безусловному перевороту в `GltfWriter.cpp`,
   с обновлением теста `TestTerrainMeshWriterBasis.cpp`.
5. Если кадр зеркален или свет лёг поперёк — стоп, разбор до причины. Дальше
   идти нельзя: этап 2 растиражирует дефект на все карты.

## 5. Дисциплина работы

- **Коммиты:** мелкие, по-русски, без трейлеров и упоминаний AI. Push — только
  по явной просьбе пользователя.
- **Каждая правка координат/угла** — с обоснованием в комментарии и ссылкой
  на первоисточник (`lwObjectMethod.cpp`, `MPMath.h`, `NetProtocol.cpp`).
  Базис менять запрещено — он один: `Q(x,y,z)=(-y,x,z)`, угол `θ−90` для
  объектов сцены, сырой для сетевых сущностей.
- **После любого изменения конвертера** — полный ctest; после изменения
  скриптов — pytest; после изменения C++ UE — сборка + `check_login.py`.
- **Не доверять зелёному прогону без снятого артефакта:** правило проекта —
  «успешный отчёт ничего не доказывает, когда соглашение живёт вне данных».
  Для визуальных изменений артефакт — кадр, для протокольных — отчёт
  `check_*.py`, для конвертера — байтовое сравнение выходов.
